# RasterDock

Начало реализации P1: передача файлов через изображение экрана.
Текущее состояние и ограничения: [implementation-status](docs/implementation-status.md).

**Сейчас:** проверенное ядро и начальный GUI. На macOS arm64 native-стенд прошёл
путь Fyne → ScreenCaptureKit → QR → verified files, включая storage reopen;
подтверждены точные физические пиксели при трёх настройках масштаба.
Critic одобрил эту ограниченную проверку и исправления; полный пользовательский
сценарий production GUI и другие ОС ещё не приняты. Не использовать для
единственной копии важных данных.
Дополнительно lead проверил передачу через два обычных экземпляра GUI с паузой
и перезапуском обоих процессов: 3/3 файла, восстановление прежнего сеанса.
См. [результат и UX-замечания](docs/validation/gui-macos.md); независимая проверка
этого прогона ограничена, полноценная UX-приёмка не заявляется.
После него исправлены путь/заголовки окон, добавлены списки сохранённых передач
и сеансов, устранены проверенные Fyne warnings. Повторный сценарий двух GUI
восстановил сеанс без ввода UUID-путей: [UX-результат](docs/validation/ux-macos.md).
См. [native-отчёт](docs/validation/native-macos.md) и
[review](docs/reviews/2026-10-25-native-validation.md).

## Разработка

Из корня проекта: Go **1.26.2**, CGO, native C toolchain и
golangci-lint **>=2.11.4, <3.0.0** локально; в CI закреплена **2.11.4**.
`GOLANGCI_LINT_VERSION` задаёт точную требуемую версию для `make lint`/`make all`;
локально по умолчанию проверяется диапазон. macOS: Xcode Command Line Tools; Linux:
компилятор, OpenGL/X11/Wayland development headers; Windows: MinGW-w64,
Git Bash и GNU Make (рецепты используют bash).

`make mod-tidy` явно обновляет зависимости; `make fmt` исправляет форматирование.
`make all` проверяет форматирование, модули, vet/lint, race/coverage,
workflow syntax и native build, не переписывая исходники.
`make build` создаёт `bin/rasterdock` (`.exe` на Windows); `make run`
запускает GUI без продуктовых CLI-параметров. `make test-coverage` создаёт
coverage.html; `make test-integration` — отдельная native-проверка.
`make help` перечисляет цели, `make clean` удаляет только build/test outputs.

CI кеширует Go modules/build cache и бинарник закреплённого линтера отдельно
для каждого runner image, архитектуры, Go и C-компилятора; на Linux ключ
также учитывает версии всех установленных пакетов после установки SDK,
включая транзитивные native-зависимости. Успешный push в
default branch сохраняет обновлённый кеш под новым ключом; PR и release tags
могут его использовать, но не обновляют общий кеш. Команды проверок выполняются
и при cache hit; стандартный Go test cache сохраняется. Первый прогон после
изменения toolchain/зависимостей холодный;
ускорение оценивается по последующему прогону. Старые записи удаляются по
политике вытеснения GitHub Actions cache; кеш не является release-артефактом.

GOTOOLCHAIN=local задаётся автоматизацией. Автоматическое обновление Go запрещено.
Каталог данных на всех ОС — `~/.config/rasterdock`, независимо от checkout.

На macOS Makefile задаёт deployment target 14.0 одновременно для CGO compilation
и linking и проверяет итоговый Mach-O `minos`. Это предотвращает случайную
сборку только для ОС разработчика, но не заменяет runtime-проверку macOS 14.

## Начальный сценарий GUI

1. `make build`, затем `./bin/rasterdock` (или `make run` для разработки).
   Выберите файл/каталог и нажмите «Подготовить». Не меняйте исходники при копировании.
2. Используйте ручные кнопки или «Показ по таймеру». Профиль этого среза:
   raw files, монохромный 1×1, B=512. Для переключения активного режима сначала «Пауза».
   «Сохранённые передачи…» открывает ранее подготовленный снимок из списка.
   Путь показан в форме и копируется целиком. Запасной способ — «Открыть
   сохранённую передачу»: выбрать каталог `prepared/`, не исходник.
3. Во втором экземпляре выберите **существующий** каталог назначения,
   обновите список окон и явно выберите viewer отправителя. Это использует
   ScreenCaptureKit и требует разрешения macOS на запись экрана.
4. Нажмите «Принимать / продолжить». UI различает durable bytes и опубликованные
   файлы. Не делайте вывод о доставке по счётчику показанных кадров отправителя.
5. Для продолжения после перезапуска откройте «Сеансы приёма…» и выберите прежний
   сеанс. Его путь и каталог назначения заполнятся автоматически, но приём
   не начнётся: заново выберите окно и нажмите «Принимать / продолжить».
   Ручной ввод путей остаётся запасным способом. Пустое поле сеанса создаёт новый
   приёмник, а не автоматически находит прежний. Payload сохраняется.

Это инструкция для проверки, **не отчёт о пройденном native сценарии**.
Windows/Linux capture пока явно недоступны. Конфликт существующего файла
останавливает публикацию без молчаливой перезаписи. После сбоя могут оставаться
служебные `.rasterdock-*.tmp`: зарегистрированные в сеансе файлы теперь
проверяются и восстанавливаются/очищаются по identity. Неизвестные файлы по
одному префиксу не удаляются; авария до первой регистрации temp всё ещё может
оставить такой файл. Во время активной передачи вручную их не удаляйте.

Системный язык выбирается по ОС. Явный выбор —
`~/.config/rasterdock/settings.yaml`, например `language: ru` (`en`/`system` также
допустимы). Настройки применяются при следующем запуске.

### Независимая проверка QR на macOS

Для каталога артефактов, созданного разработчиком:

```sh
RASTERDOCK_TEST_ARTIFACTS="$ARTIFACT_DIR" GOTOOLCHAIN=local go test -count=1 ./internal/adapters/codec
swift scripts/verify-qr.swift "$ARTIFACT_DIR/mono.png" "$ARTIFACT_DIR/mono.json"
```

Apple Vision — второй decoder, независимый от Go-адаптера. Swift нужен только
разработчику для проверки, не пользователю executable. Этот тест не читает экран.

## CI и поставка

Workflows используют native runners с CGO. Локальная синтаксическая проверка
не равна hosted CI или проверке на чистой пользовательской ОС. Release пока
явно блокирует публикацию на шаге macOS signing: credentials и проверенная
подпись ещё не настроены. Неподписанный dev build не является выпуском.
